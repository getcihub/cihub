# APIs

Contexte : qui ajoute ou modifie une route, un code d'erreur, un webhook sortant ou une commande de la CLI. Le code est la source de vérité (`AGENTS.md` D1) ; ce fichier dit l'intention.

L'API publique est une REST orientée ressources sous `/api/v1`, sur l'adresse de l'instance, à côté du tableau de bord (`https://cihub.example.com/api/v1`) ; elle a des erreurs structurées, un endpoint de liste des files, et une réponse de création qui renvoie la file. L'authentification se fait par `Authorization: Bearer <token>` avec des jetons d'API portés par l'organisation (scopes `queues:read`, `queues:write`, `prs:write`, `targets:write`, `metrics:read`) ou par une session du tableau de bord ; la CLI utilise la même API.

| Méthode            | Chemin                                                   | Rôle                                                                                                                                                                                                                                            |
| ------------------ | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET                | `/repos`                                                 | Dépôts visibles par le jeton                                                                                                                                                                                                                    |
| GET, POST          | `/repos/{owner}/{name}/queues`                           | Lister les files, en créer une (`target_branch`, `mode`, réglages) ; la création est réservée aux admins et renvoie la file                                                                                                                     |
| GET, PATCH, DELETE | `/queues/{queue_id}`                                     | Lire, modifier partiellement les réglages ou `state`, supprimer quand la file est vide                                                                                                                                                          |
| GET                | `/queues/{queue_id}/items`                               | Entrées vivantes et historique, filtres `state`, `since`, `until`, pagination par curseur `take` ≤ 100                                                                                                                                          |
| POST               | `/queues/{queue_id}/items`                               | Soumettre une PR : `pr_number`, `priority` (nom ou 0–255), `no_batch`, `direct`                                                                                                                                                                 |
| GET                | `/queues/{queue_id}/prs/{pr_number}`                     | Entrée courante d'une PR, `?include=timeline` ; recherche par `?branch=` également                                                                                                                                                              |
| POST               | `/queues/{queue_id}/prs:batchGet`                        | Jusqu'à 50 PR par numéro ou par branche, renvoie `not_found[]`                                                                                                                                                                                  |
| POST               | `/items/{item_id}/cancel`, `/items/{item_id}/restart`    | Annuler ou relancer les tests                                                                                                                                                                                                                   |
| GET                | `/queues/{queue_id}/graph`                               | Le graphe de merge en nœuds et arêtes pour le tableau de bord                                                                                                                                                                                   |
| GET                | `/test-runs/{run_id}`                                    | Détail d'une exécution (format ci-dessous, figé au lot 6, `AGENTS.md` D115) : branche, SHA, tous les check runs et statuts observés avec les requis marqués, PR testées, cibles impactées, dépendants                                           |
| GET                | `/queues/{queue_id}/test-results`                        | Une ligne par PR et par tentative sur une plage (≤ 45 jours) : `outcome` (`passed`, `failed`, `interrupted`, `cancelled`), `cycle_conclusion`, `bisection` (`entered_bisection`, `in_bisection`), `run_id` ; pagination par offset avec `total` |
| POST               | `/repos/{owner}/{name}/prs/{pr_number}/impacted-targets` | Corps `{head_sha, targets}` avec une liste ou `"ALL"` ; limite 20 Mo ; accepte aussi un identifiant de workflow de fork à la place d'un jeton                                                                                                   |
| POST               | `/queues/{queue_id}:resync`                              | Admin : relire depuis GitHub chaque PR vivante et chaque exécution                                                                                                                                                                              |
| GET                | `/metrics`                                               | Exposition Prometheus, filtres `repo`, `branch`                                                                                                                                                                                                 |
| GET, POST, DELETE  | `/orgs/{org}/webhooks`                                   | Gérer les endpoints de webhooks sortants, tester une livraison                                                                                                                                                                                  |
| GET                | `/orgs/{org}/audit`                                      | Changements de réglages et actions d'admin                                                                                                                                                                                                      |

**`GET /test-runs/{run_id}`** rend un objet JSON dont les champs sont les colonnes de `test_runs` et de
`check_observations` (`docs/DATA_MODEL.md`), avec les noms du vocabulaire fermé : `id`, `queue_id`, `group_id`,
`attempt`, `status`, `status_reason`, `test_branch`, `test_sha`, `base_sha`, `draft_pr_number`,
`tested_pr_numbers`, `head_shas` (les têtes mergées dans l'ordre : prédécesseurs puis membres),
`predecessor_pr_numbers`, `required_statuses`, `required_statuses_source`, `started_at`, `ended_at`,
`last_report_at`, `failure_reason`, `failure_causing_statuses`, `conflict_culprit` (`{kind: queue_pr, pr_number}`
ou `{kind: base_branch}`), `checks` (une entrée par check observé : `name`, `kind`, `required`, `conclusion`,
`details_url`, `observed_at`), `impacted_targets` (`all` ou la liste, lot 13) et `dependents` (les exécutions
vivantes dont les prédécesseurs contiennent une PR testée : `run_id`, `pr_numbers`). Une valeur absente est
`null`.

Les erreurs sont en `application/problem+json` avec `type`, `title`, `status`, `detail` et un `code` machine (`queue_not_empty`, `pr_is_draft`, `pr_not_found`, `queue_paused`, `targets_required`, `rate_limited`). Limite de débit : 600 requêtes par minute et par jeton, `Retry-After` sur les 429. Le document OpenAPI 3.1 est généré depuis le code (`cihub-web`, `cihub-api-types`) et publié sur `/api/v1/openapi.json` ; le client TypeScript du tableau de bord en est dérivé, et le client Rust `cihub-client` partage directement les types de `cihub-api-types`.

Les webhooks sortants suivent la spécification [Standard Webhooks](https://www.standardwebhooks.com) (en-têtes `webhook-id`, `webhook-timestamp`, `webhook-signature` en HMAC-SHA256), sont retentés avec backoff exponentiel sur 24 heures et désactivés après 7 jours d'échecs. Les types d'événements, les champs des payloads et les raisons suivent le vocabulaire de CIHub (`docs/DOMAIN.md`), sans traduction vers celui d'un autre produit (`AGENTS.md` D139) ; leur liste est figée au lot 11. Les événements par PR sont émis pour chaque membre d'un lot.

La CLI (`cihub`) est un client mince, distribué seul et sans aucun code serveur ; elle ne parle qu'à l'API publique : `cihub login`, `cihub merge <pr> [-p urgent|high|low|0-255] [--no-batch]`, `cihub cancel <pr>`, `cihub restart <pr>`, `cihub status [<pr>]`, `cihub queue pause|resume|drain`, `cihub queue graph`, `cihub targets upload --pr <n> --sha <sha> --file targets.txt` ; le dépôt et la branche cible sont déduits du remote git et de la branche de base de la PR.

Les interfaces internes ne sont pas du RPC : les processus partagent Postgres, donc l'« API interne » est constituée des tables `jobs` et `outbox` et des canaux `NOTIFY` `cihub_queue`, `cihub_jobs`, `cihub_outbox`.
