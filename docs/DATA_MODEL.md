# Postgres data model

Postgres 17 holds the operational state: 23 tables; each one, except `scm_instances` and `users` (global), belongs to a tenant and carries `org_id` and an index that starts with it, so that isolation is enforced by row level security rather than by application discipline. Identifiers are ULIDs (`DECISIONS.md` D4; time-ordered, index-friendly), stored as `text` in their typedid form (`org_0627…`, D37); timestamps are `timestamptz`; enumerations are Postgres enums mirrored by the enumerations of `cihub-domain` (`docs/DOMAIN.md`) and compared by a test. No column depends on an SCM (`DECISIONS.md` D46): an SCM identifier is an `external_id` in `text`, unique within its SCM instance only.

The `queue_items` row is the hot path. Its state machine is guarded in SQL: each transition is an `UPDATE ... WHERE id = $1 AND state = $2` whose row count is checked, so that two reconcilers can never apply the same transition, even if the advisory lock were lost. `position` is the materialized queue order described in [ALGORITHMS.md](ALGORITHMS.md), assigned in steps of 1,000 and renumbered by the reconciler when a gap is exhausted, indexed by `queue_items (queue_id, position) WHERE is_current AND state NOT IN ('merged','failed','cancelled')`. `is_current` has a partial unique index on (`queue_id`, `pr_number`): a PR therefore has at most one live item, while its history stays queryable, through an index on (`queue_id`, `pr_number`) over all the items, which the history of the PR comment reads (`DECISIONS.md` D244).

The settings of a queue are not written by the interface: they come only from the `.cihub.yaml` file of the repository, validated by `cihub-config` (`docs/CONFIGURATION.md`, `DECISIONS.md` D134). `config_text` keeps the last valid file read on the head of the target, `config_sha` the head of the last read and `config_error` the reason a read file is refused (D136). A change of `mode` or `merge_method` is recorded as an event with its actor, and a mode change with items in flight switches the queue to `switching_modes`.

Retention: `webhook_inbox` rows are deleted 7 days after processing, `done` `jobs` after 3 days, `events` partitions are deleted 90 days after the end of their month, when a snapshot covers each of their events (`DECISIONS.md` D106) (ClickHouse keeps the long history), `test_runs` and `check_observations` after 180 days, and `queue_items` is kept as long as the organization exists. Indexes beyond the primary keys: `jobs (class, run_after)` partial on waiting jobs, `jobs (connection_id, locked_until)` partial on running jobs, `webhook_inbox (queue_id, received_at) WHERE processed_at IS NULL`, `webhook_inbox (received_at) WHERE routed_at IS NULL`, `events (queue_id, seq)`, `events (item_id, occurred_at)`, `events (run_id)` partial on the events of a run, `test_groups (queue_id)`, `test_runs (queue_id, status)` partial on running runs, `test_runs (tested_pr_numbers)` (GIN: the runs of a PR, for its history), `queues (dirty, next_tick_at)`.

Row level security is enabled and forced on every table that carries `org_id`, and on `orgs` (`DECISIONS.md` D38). Every table has the `tenant` policy: `cihub_system() OR org_id = cihub_org_id()`, for reads and writes alike; a migration sets both with `cihub_tenant_table(table)`. `cihub_org_id()` reads the transaction parameter `cihub.org_id`, which `cihub_store::begin_org` sets; the API uses it after authentication. `cihub_system()` reads `cihub.system`, which `cihub_store::begin_system` sets for the work that does not know the organization yet (authentication by token fingerprint) or that walks through all of them (the scheduler, the partitions); these queries always filter by `queue_id` or `org_id`. A transaction without context sees no row. The CIHub Postgres role is neither superuser nor `BYPASSRLS`, otherwise it would see everything: `cihub server` checks it at startup. `scm_instances` and `users` are the only global tables (D39, D47). A test (`every_tenant_table_forces_row_level_security`) fails when a table that carries `org_id` lacks its policy.
