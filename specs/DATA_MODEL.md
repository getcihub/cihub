# Postgres data model

Postgres 17 holds the operational state: 32 tables; each one, except `users`, `sessions` and `device_codes` (global), belongs to a tenant and carries `org_id` and an index that starts with it, so that isolation is enforced by row level security rather than by application discipline. Identifiers are ULIDs (time-ordered, index-friendly), stored as `text` in their typedid form (`org_0627…`); timestamps are `timestamptz`; enumerations are Postgres enums mirrored by the enumerations of `cihub-domain` (`specs/DOMAIN.md`) and compared by a test. No column depends on an SCM: an SCM identifier is an `external_id` in `text`, unique within the deployment, which serves a single SCM.

The `queue_items` row is the hot path. Its state machine is guarded in SQL: each transition is an `UPDATE ... WHERE id = $1 AND state = $2` whose row count is checked, so that two reconcilers can never apply the same transition, even if the advisory lock were lost. `position` is the materialized queue order described in [ALGORITHMS.md](ALGORITHMS.md), assigned in steps of 1,000 and renumbered by the reconciler when a gap is exhausted, indexed by `queue_items (queue_id, position) WHERE is_current AND state NOT IN ('merged','failed','cancelled')`. `is_current` has a partial unique index on (`queue_id`, `pr_number`): a PR therefore has at most one live item, while its history stays queryable, through an index on (`queue_id`, `pr_number`) over all the items, which the history of the PR comment reads.

The settings of a queue are not written by the interface: they come only from the `.cihub.yaml` file of the repository, validated by `cihub-config` (`specs/CONFIGURATION.md`). `config_text` keeps the last valid file read on the head of the target, `config_sha` the head of the last read and `config_error` the reason a read file is refused. A change of `mode` or `merge_method` is recorded as an event with its actor, and a mode change with items in flight switches the queue to `switching_modes`.

Retention: `webhook_inbox` and `queue_inbox` keep no history, a row is deleted when it is processed; `done` `jobs` are deleted after 3 days, expired `sessions` and `device_codes` by the daily maintenance, `events` partitions are deleted 90 days after the end of their month, when a snapshot covers each of their events (ClickHouse keeps the long history), `test_runs` and `check_observations` after 180 days, and `queue_items` is kept as long as the organization exists. Indexes beyond the primary keys: `jobs (class, run_after)` partial on waiting jobs, `jobs (connection_id, locked_until)` partial on running jobs, `jobs (queue_id, type)` partial on waiting and running jobs (whether a queue has a job of a type in flight), `webhook_inbox (queue_id, received_at)`, `webhook_inbox (received_at) WHERE connection_id IS NULL`, `queue_inbox (queue_id, arrival)`, `events (queue_id, seq)`, `events (item_id, occurred_at)`, `events (run_id)` partial on the events of a run, `test_groups (queue_id)`, `test_groups (queue_id)` partial on the live groups (the graph), `test_runs (queue_id, status)` partial on running runs, `test_runs (queue_id, started_at)` (the recent runs of a queue, for the history of its PRs), `test_runs (test_sha)` (the run of a test commit, at each report of a check), `test_runs (group_id)` (the run of an item), `test_runs (queue_id, ended_at)` partial on succeeded runs (the median duration of a run), `queue_items (pr_author_id)` partial on the live current items and `queue_items (pr_author_id, state_changed_at)` partial on the merged current items (the PRs of a person), `queue_items (queue_id, state_changed_at)` partial on the ended current items (the counters and the tabs of the last 24 hours, the last merge), `queue_items (org_id, submitted_at DESC, id DESC)` partial on the current items (the PRs of an organization, the newest first), `users (lower(login))` (a person by their login), `queues (dirty, next_tick_at)`, `memberships (user_id)` (the organizations of a user), `sessions (expires_at)` and `device_codes (expires_at)` (the purge by the maintenance).

Row level security is enabled and forced on every table that carries `org_id`, and on `orgs`. Every table has the `tenant` policy: `cihub_system() OR org_id = cihub_org_id()`, for reads and writes alike; a migration sets both with `cihub_tenant_table(table)`. `cihub_org_id()` reads the transaction parameter `cihub.org_id`, which `cihub_store::begin_org` sets; the API uses it after authentication. `cihub_system()` reads `cihub.system`, which `cihub_store::begin_system` sets for the work that does not know the organization yet (authentication by token fingerprint) or that walks through all of them (the scheduler, the partitions); these queries always filter by `queue_id` or `org_id`, or by `user_id` for the organizations of a session user. A transaction without context sees no row. The CIHub Postgres role is neither superuser nor `BYPASSRLS`, otherwise it would see everything: `cihub-server` checks it at startup. `users`, `sessions` and `device_codes` are the only global tables: a session covers every organization of its user, a device code belongs to no organization, and the organization of a request is checked through `memberships`. A test (`every_tenant_table_forces_row_level_security`) fails when a table that carries `org_id` lacks its policy.
